Case study

Qansei

An emotional-intelligence assistant for iMessage — and an exercise in piping some of the most sensitive data a person has through an LLM without ever storing it.

Qansei watches one conversation you choose — typically your partner's — and helps you show up better in it. A menu-bar Mac app notices new messages, Claude reads the emotional weather, and your iPhone gets a nudge when something deserves more attention than you gave it, plus a daily summary of how the conversation went. It's a complete product, not a demo: Firebase auth, Stripe subscriptions, a signed and notarized Mac DMG, and a companion iOS app on the App Store.

Both apps share a local Swift package (QanseiShared) for models and API plumbing; the analysis prompt lives server-side so it can evolve without shipping app updates.

The privacy contract

The design premise: the user is trusting the product with their most personal conversation, so every layer is built to hold as little as possible.

  • Single-conversation scope. Only the selected chat is ever read for content; the conversation picker sees metadata only. Access to chat.db is read-only — the app cannot send iMessages, and Full Disk Access must be granted by hand.
  • Messages are transient. They travel to the Cloud Function for analysis and are never written to Firestore or any database. What persists is alert metadata and daily summaries written in pattern language — never message content.
  • Rules-enforced boundaries. Alerts are writable only by the Cloud Function; users can't edit their own history. Internal context profiles used to improve future analysis are read-blocked at the Firestore-rules layer — not even the account owner can fetch them.
  • Secrets stay out of the codebase. The Anthropic API key lives in Google Cloud Secret Manager, injected at function runtime.

Engineering notes

  • chat.db is hostile territory. macOS treats the Messages database as its own — reads race WAL checkpoints, and transient SQLite errors are expected behavior to tolerate, not bugs to fix. The monitor is built around that reality.
  • Right-sized model. Tone classification on a message window doesn't need a frontier model — Haiku 4.5 keeps the always-on loop fast and cheap. The function short-circuits entirely on empty days rather than paying for a no-op summary.
  • Strict output contract. Claude's verdict must parse as JSON; failures are logged with truncated raw output for diagnosis rather than silently dropped.
  • Two distribution models, one codebase. The Mac app can't be sandboxed (it needs chat.db), so it ships as a notarized DMG with its own update path, while the iOS companion lives on the App Store — with Stripe rather than IAP handling the subscription.

Built with Claude

Qansei was built by one engineer with Claude Code as the pair — roughly ninety percent of commits are co-authored. Claude also runs in production as the analysis engine, which made the privacy contract a design constraint on both sides: the tool that helped write the system is the same one the system must be careful with.
